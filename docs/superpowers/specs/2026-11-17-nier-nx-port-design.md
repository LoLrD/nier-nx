# nier-nx: NieR (Xbox 360, 2010) на Nintendo Switch — дизайн

Дата: 2026-11-17

## Зачем

Пользователь хочет пройти NieR на своей Switch — нативным портом, как те, что в 2026 году
сообщество делает через статическую рекомпиляцию Xbox 360 (Mass Effect, Prototype, Gears 2, MGR).
Готового порта NieR на Switch нет: есть только WIP-ролик PC-рекомпа на ReXGlue и ARM64-проект
`NextOs-Ports/nier-decomp` на нулевой стадии (образ даже не распакован, цель — Mali/GLES2, не Switch).

Изначально хотелась версия Replicant (герой — брат). На Xbox 360 вышла только версия с отцом
(в Японии — Gestalt, на Западе — просто NieR). Решение: портируем 360-версию; подмена героя на
брата — отдельный будущий этап со своим дизайном, сюда не входит.

Это личный проект: играть самому. Публикация кода без игровых данных — возможна позже, не цель.

## Целевое железо

- Switch OLED (Mariko), чип, CFW-сборка UltraNX 3.0 (модифицированный Atmosphère + Hekate +
  Horizon OC), HOS 22.5.0, emuMMC. Разгон через Horizon OC доступен.
- Установка NSP через DBI; на Маке есть `~/work/switch-ultra/dbi-usb.py` для установки по USB из консоли.
- Машина разработки: MacBook на Apple M4, 16 ГБ, macOS 27, arm64.

## Цели

1. NieR проходится от начала до конца на Switch OLED: без вылетов на сюжетном пути, с сохранениями,
   звуком (XMA), управлением с Joy-Con/Pro Controller.
2. Производительность: **30 FPS на стоковых частотах или минимальном разгоне** — главный
   критерий пользователя. Качество графики жертвуется без ограничений (слова пользователя:
   «по графике пофиг»): низкое внутреннее разрешение + FSR 1, отключение/упрощение
   постэффектов, теней, дальности прорисовки — всё допустимо ради 30 FPS. Минимальный разгон —
   ориентир CPU ≤ ~1785 МГц, GPU ≤ ~921 МГц, без поднятия напряжений. Для сравнения: Prototype
   даёт 22–30 FPS только на CPU 1963 / GPU 1152 / RAM 2333 МГц — основной упор будет в CPU
   (главный поток), и графические урезания его не решат, нужны оптимизации горячих путей.
   Основной режим — в руках (экран OLED 720p); в доке то же внутреннее разрешение с апскейлом
   *(моё решение, пользователь режим не уточнял)*.
3. DLC «15 Nightmares» работает (пакет XContent из дампа пользователя).
4. Весь текст игры — на русском (см. этап 5).
3. Разработка устроена так, чтобы пользователь подключался к тестам, когда на экране уже есть
   что смотреть, а не на этапе «упало при старте».

## Не цели

- Герой-брат, катсцены/озвучка Replicant (будущий отдельный этап).
- Ремастер Replicant ver.1.22 (x86/DX11) и PS3-версия Replicant.
- Онлайн, достижения, мультиплеер.
- Другие DLC, которых нет в дампе пользователя.
- Русская озвучка (только текст и субтитры).
- Отполированная Mac-версия как цель. Мак — платформа отладки; играбельная Mac-сборка — бонус,
  если графика там заведётся почти бесплатно (см. этап 1б).
- Поддержка первой ревизии Switch (Erista) и Switch 2 — не проверяем, не оптимизируем.

## Анти-цели (провал, даже если «работает»)

- Игровые данные, `default.xex`, сгенерированный из него C++, шейдеры игры, `prod.keys`, файлы
  чужого фанатского перевода попадают в репозиторий или в релиз.
- Порт формально грузится, но играть нельзя: < 20 FPS в обычных локациях, регулярные вылеты,
  поломанные сохранения.
- Каждый шаг ранней отладки требует ручного запуска на консоли пользователем.

## Ограничения

- Только копия игры пользователя. Дампы лежат в `~/Downloads`:
  `Nier (USA, Europe) (En,Ja,Fr,De).7z` → Redump ISO 7.8 ГБ (USA/Europe, языки En/Ja/Fr/De)
  и `NIER - 15 Nightmares (World) (DLC).zip` → пакет `535107E8/00000002/…` (title ID 535107E8).
  Распаковываем в `~/work/nier-nx-data/` — вне репозитория. Title Update в дампе нет, поэтому
  порт строится на базовом `default.xex` с диска *(моё решение; смена xex позже обнуляет все
  адресные правки, так что выбор окончательный)*. SHA-256 xex фиксируем в репозитории, сам файл — нет.
- Эталона нет: ни x86-ПК с Xenia, ни прошитого 360. Баги кодогена и графики ищем без сравнения
  с оригиналом — только по логам, трассировке и здравому смыслу. Закладываем на этапы 1–3
  больше времени.
- Switch: 4 ГБ RAM, игре доступны 3 ядра A57 (4-е у системы). Запуск только в полном режиме
  приложения (через NSP-форвардер или hbmenu поверх игры с зажатым R); applet-режиму (Альбом)
  не хватает памяти. Форвардеру нужно 39-битное адресное пространство.
- Тулчейн Switch: devkitA64/libnx в Docker (образ `devkitpro/devkita64`). Docker на Маке —
  OrbStack, сейчас не запущен.
- Лицензии заимствований: код порта masseffect-nx — GPL-3.0, правки SDK — BSD-3-Clause,
  правки Mesa и транслятор шейдеров — MIT. Если берём код порта masseffect-nx, наш репозиторий —
  GPL-3.0. ReXGlue — своя лицензия, сохраняем уведомления (`THIRD_PARTY_NOTICES.md`).
- Форвардер NSP собирается с `prod.keys` пользователя; ключи никогда не коммитятся.

## Подходы (рассмотренные)

1. **Сначала полноценный Mac-порт, потом Switch.** Плюс: вся отладка без пользователя.
   Минус: графика на Маке идёт через Xenos-Vulkan-бэкенд ReXGlue поверх MoltenVK, а Switch-порты
   используют собственный рендерер — вложения в Mac-графику на Switch почти не переносятся.
2. **Сразу Switch.** Плюс: сразу целевое железо и проверенная подкладка masseffect-nx.
   Минус: десятки ранних запусков «упало на старте» требуют пользователя.
3. **Гибрид (выбран пользователем).** На Маке — рекомпиляция и прогон без графики (null-драйвер)
   до стабильной работы игровой логики; затем Switch с подкладкой и рендерером masseffect-nx.
   Исправления кода игры (границы функций, таблицы переходов, шимы ядра, хуки) общие для обеих
   платформ, потому что сгенерированный C++ один и тот же.

## Решения о том, как строим

Решено с пользователем:
- Игра: NieR (Xbox 360, 2010), версия с отцом.
- Подход: гибрид (см. выше).

Мои решения (пользователь может поправить):
- **Рекомпилятор:** ReXGlue SDK. Версию фиксируем на той, с которой собран masseffect-nx
  (его `sdk/` — ReXGlue с Horizon-слоем и правками кодогенератора), чтобы Mac- и Switch-сборки
  использовали один и тот же кодоген.
- **Switch-подкладка и рендерер:** из masseffect-nx — Vulkan на NVK (mesa-switch), офлайн-трансляция
  шейдеров XenosRecomp + DXC, эмуляция EDRAM изображениями по форматам. Причина: на ней уже
  сделан второй порт (Prototype), и это Vulkan — тот же API, что на Маке.
  Запасной вариант, если NVK упрётся в производительность: рендерер Renut на deko3d
  (на нём MGR, MK9, Sonic Adventure 2 с 60 FPS на стоковых частотах).
- **Цикл тестов на Switch** (пользователь разрешил Wi-Fi для emuMMC и отладочный sysmodule;
  его 90DNS-блокировки остаются): sysmodule в духе sys-botbase — удалённый запуск приложения,
  нажатия кнопок, скриншоты по сети; nxlink по Wi-Fi — отправка NRO и поток логов на Мак.
  Цель — чтобы я сам гонял итерации на консоли. NSP-форвардер через DBI/`dbi-usb.py` — для
  обычной игры.
- **Репозиторий:** `~/work/nier-nx`, git. Игровые данные — вне репозитория
  (путь задаётся переменной/конфигом), `.gitignore` закрывает `game/`, `generated/`, `*.xex`,
  `*.iso`, ключи.

## Этапы и критерии готовности

0. **Подготовка.** Распаковка дампов из `~/Downloads` в `~/work/nier-nx-data/` (7z → ISO →
   extract-xiso; DLC — из zip), SHA-256 `default.xex`. Установка cmake, ninja, Vulkan SDK,
   запуск OrbStack, образ devkitA64.
   *Готово, когда:* хэш зафиксирован, `rexglue codegen` отрабатывает на xex.
1. **Mac, без графики.** Сборка под macOS arm64 с `gpu.driver = null`. Чиним кодоген и рантайм:
   границы функций, jump tables, недостающие шимы ядра/XAM, файловый ввод-вывод, потоки.
   *Готово, когда:* игра штатно проходит загрузку, уходит в главное меню и загружает первую
   локацию (видно по логам: файлы уровня прочитаны, PM4-свопы идут стабильно), 10+ минут без
   вылета, с автоматическим вводом-заглушкой где нужно.
1б. **Mac, графика (опционально, таймбокс 2 дня).** Пробуем `gpu.driver = vulkan` через MoltenVK.
   Если картинка появляется — Mac-сборка остаётся как бонус и как удобный визуальный отладчик.
   Если нет — не чиним, идём дальше.
2. **Switch, первый кадр.** Подключаем Horizon-слой, рендерер и Mesa из masseffect-nx,
   офлайн-шейдеры для NieR, сборка NRO, запуск по nxlink.
   *Готово, когда:* на консоли виден титульный экран.
3. **Switch, играбельность.** Графические баги, звук XMA, ввод, сохранения, загрузки.
   Пользователь проходит игру и сообщает о проблемах.
   *Готово, когда:* сюжет проходится до финала A без блокирующих багов.
4. **Производительность.** Профили частот Horizon OC, динамическое/настраиваемое внутреннее
   разрешение + FSR 1, прогрев кэша пайплайнов, горячие пути (NEON, сокращение постэффектов).
   *Готово, когда:* выполнена цель 2 в основных локациях.
5. **Русский текст из перевода ремастера** (решение пользователя). Официального русского у
   ремастера Replicant ver.1.22 нет; есть фанатские переводы текста и субтитров (ZoG/hezz —
   бесплатные, The Miracle — платный, через VK). Схема:
   - Пользователь сам получает файлы выбранного перевода (выбор перевода и наличие у пользователя
     самого ремастера уточняем в начале этапа). В репозиторий они не попадают — как игровые данные.
   - Инструмент сопоставления: английские строки 360-версии ↔ строки ремастера (по ID, где они
     совпадают по происхождению, иначе нечётким сравнением по английскому тексту). Совпавшим
     строкам берём русский из перевода.
   - Строки, которых в ремастере нет или которые там другие (версия с отцом: Йона — дочь, не
     сестра; обращения «папа» вместо «брат»; DLC), перевожу сам в стиле и глоссарии выбранного
     перевода.
   - Кириллица: добавляем глифы в шрифты игры (генерация атласов в формате движка) и подменяем
     текстовые ресурсы при загрузке, не трогая `default.xex`.
   *Готово, когда:* основной сюжет, меню, предметы, квесты и DLC — на русском без «квадратиков».
6. **Упаковка.** NSP-форвардер, конфиг, инструкция установки «со своей копией»; русский —
   отдельный шаг установки из файлов перевода пользователя.

## Роль пользователя

- Этап 0: дать образ игры.
- Этапы 0–1(б): не нужен.
- Этап 2: один раз подключить консоль к Wi-Fi и поставить отладочный sysmodule (по моей
  инструкции); держать консоль включённой во время сессий отладки.
- Этапы 3–4: проходить игру и сообщать о проблемах; ручные запуски — только если удалённый
  контроль не справляется.
- Этап 5: собрать форвардер со своими `prod.keys` (или дать путь к ним локально).
